# 1.4.0 升级记录

1.4运行代码已在[修复后四格CI](https://github.com/SoberAming/codex-project-storage/actions/runs/43557649569)通过，证据绑定修订`b75a54ccd85f8cb55561bc84c6db1eba89877f15`。最终发布tag仍须绑定其精确修订通过的发布检查；该运行不代替后续文档提交的最终检查。组件SHA和历史记录保留在`references/verification.json`，1.3结果不为新增执行能力背书。

## 解决的问题

画像能测到主要占用，旧版却经常只有很小的CPython缓存执行计划。历史隔离测试数据库被整体归为保护对象，项目npm缓存仅有建议路线。这限制了实际收益。

1.4增加独立的合成PG测试data退役与项目独占npm10.9.2缓存适配，不把所有数据库或缓存加入通用白名单。画像还会汇总覆盖主要占用的类别，要求解释大项的必要性、具体处理条件与证据缺口。

## 使用变化

- 测试运行必须核实真实生产器、合成输入、对应运行结束、日志/结果保留、当前引用与活动；不能只声明“测试、可重建”。符合条件时仅退役精确data子树，业务库和恢复链保留。
- npm只支持经过独占归属和真实生产记录核验的受支持版本内容缓存。先隔离精确缓存命名空间再运行固定原生命令；保留日志，失败保留真实位置与回执。
- 兼容官方Node分发中缺省的内置`npm/npmrc`。只接纳普通且身份稳定的安装目录中该叶文件明确不存在；存在时仍绑定完整SHA。缺父目录、链接、权限/I/O错误及检查间出现或漂移继续拒绝，其他实现文件仍为必需。探测前后和原生清理前均复核，不写入npm安装配置。
- 实际执行仍需用户已选择具体方案。仅分析请求不会触发删除；未执行的收益为0。
- 占用不等于可回收量，项目外卷空闲变化不能自动归因给当前项目。安全收益不够时，明确差额并提出有限扩展分析。

## 验证与限制

修复后的托管矩阵使用Node22.14.0/npm10.9.2，Windows X64与macOS ARM64（`macos26`）各运行Python3.10.11和3.13.17。每格10套共258项，Windows每格256通过、2项Apple原生ACL测试跳过；macOS每格254通过、4项Windows专用测试跳过。当前npm套件为64项，测试退役套件为40项；具体镜像、跳过名称和范围见[兼容性记录](COMPATIBILITY.md)。仓库校验及仓库外安装包构建也在四格成功。

1.4的[首次失败CI](https://github.com/SoberAming/codex-project-storage/actions/runs/43556855654)保留，原因是此前将可缺省的内置`npm/npmrc`视为必需实现文件。上述修正后四格通过，没有跳过原生集成或放宽未知错误。早期Windows/Python3.13.13的246项、237通过、9跳过及32组独立目标复核保留为历史本机证据，不改写旧版116项等历史测试，也不计为当前258项结果。

四格均实际执行原生npm集成，只使用全新无脚本本地包和独占缓存；每格清理2个缓存文件，逻辑字节Windows为878、macOS为894，保留原包、生产记录及原日志，不触及真实用户缓存。测试退役的真实CLI在四格均处理6个虚构PG布局文件、29,461,707逻辑字节，真实查询系统活动，没有启动或连接PG、执行项目代码。逻辑删除量不等于卷空闲增量。

独立正向试用只读取已有项目快照、少量生产器和日志，真实项目删除及迁移均为0。托管样本不等于个人Mac、外盘、完整APFS克隆/快照或业务工作流、真实PG服务器及真实业务数据库的验收。

测试退役器不是数据库备份工具；未证明可丢弃的数据继续保留。冷文件拷贝不等于跨版本、跨平台恢复验证。macOS协作锁不能阻止不合作写入者；无法核实静止时停止释放。
