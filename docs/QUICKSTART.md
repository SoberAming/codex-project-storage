# 使用示例

在需要处理的具体项目里调用。Agent负责查用途、范围、生产依据、引用和使用条件，用户决定结果。不要把多项目父目录或整块磁盘随手当当前项目。

## 先了解占用

```text
$codex-project-storage 先只读分析这个项目所在磁盘。说明占用最多的3到5类数据、生产工具、用途、是否共享，以及哪些能核实处理。给我一个推荐方案，说明空间收益、影响和保留内容，不要先删除。
```

一次快照能解释当前大小；判断增长需要相同范围、策略和完整程度的前后快照。修改时间只能当线索。

## 想直接推进已确认范围

```text
$codex-project-storage 按我们刚才确认的清单执行组合方案。删除经核实可重建的中间产物，迁移需保留且已经停用的导出。你管理计划和校验参数；内容、身份、用途或静止条件变化时停止，记录已完成和未处理部分。
```

这要求上下文中存在具体方案及明确授权。不能把这个示例自动当成所有新用户都授权删除。

## 有移动盘，希望保存旧成果

```text
$codex-project-storage 我有一个已连接的外部存储位置，想保留旧成果。请先发现实际卷和容量，核实哪些停用产物适合迁移，说明断连影响和取回方式。我选择目标和方案后再执行，当前项目与会话保留。
```

迁移先复制并核验，再确认可用，最后释放源。需要旧路径兼容、修改工程引用或搬活动数据库的对象另立方案，当前通用执行器不自动处理。

## 视频或图片任务产生很多临时文件

```text
$codex-project-storage 重点分析本项目的解码帧、普通预览和重复导出。核对原输入、生产脚本、依赖、运行引用和重建方式。可重建中间产物与需保留成果分开；AI唯一结果、成片、验收截图和原素材保留。先告诉我推荐处理范围。
```

生成中间件符合规则时可直接精确删除，不要求先保存同一批输出的重复副本。输入和生产依据保留。当前工具不会实际重建来证明结果，因此不能把一次模型调用或外部服务重新运行当确定重建。

## 没有manifest的研究或资料项目

```text
$codex-project-storage 这个目录没有标准工程配置。请按元数据、项目说明和实际生产关系分析占用，不要因为类型未知停止，也不要按扩展名或旧时间直接删除。给我有证据的方案，未知的保留继续查。
```

## 需要达到明确空间目标

```text
$codex-project-storage 我希望项目所在卷至少再释放10 GiB。先核实可安全处理的范围和真实可用目标，给出方案；如果安全收益不足，说明缺口，不为凑数量扩大删除范围。
```

目标由用户提出，Skill不默认给所有用户设同一个水位。可释放的逻辑量、已知分配估计和卷空闲实测差值需分别报告。
