# 1.6 · 大项目分批扫描与历史构建清理

大项目的总体积很大，但扫描触及上限、硬链接混在目录中、历史任务缺少结束日志时，旧工具可能只能给出很小的缓存方案。1.6 增加实际工具，逐步把这类线索变成有边界、可以复核和执行的计划。

## 新增工具

project_batches.py 创建项目外的持久清单，按独立任务或准确产物根分批处理元数据。每批有时间和成员预算，下次继续待办队列；保存真实路径和全局文件身份。目录在续扫前变化时，该单元进入错误状态，其余单元继续。底层读盘错误立即停止。报告区分所选单元完成、全项目覆盖、排除范围与尚未核验的独立文件占用。

build_artifact_guard.py 提供停用 Next 候选的 plan/apply。它核实相邻真实构建配置、保留源码、构建 ID、明确检查的启动配置、保留的当前与回退应用、原生进程及服务实际提供的静态构建内容。当前使用、引用不明或身份变化时拒绝处理。工具不执行项目代码、安装、构建或进程终止。

执行范围是独立生成的编译代码与已识别 webpack 缓存，包括 .next/dev 中对应的隔离开发输出。共享文件逐个保留，其余独立文件可继续核验；源码、会话、索引、数据库、恢复资料、构建身份、根清单、预渲染内容、媒体及未知产物保留。旧候选清理后再次运行前需要重新构建。

历史任务没有可信结束记录时，新构建政策使用明确的现状核验，不把现状评审伪装成历史事实，也不放宽其他任务或数据库执行器的条件。当前引用检查限于已审查输入和可见运行状态，不能声称穷尽任意消费者。

## 验证边界

新增分批续扫、准确归属、硬链接逐文件保护、真实隔离 CLI 删除、活动写入拒绝、成员/来源变化拒绝和状态保留样本。所有旧测试继续执行。Windows/macOS 与 Python 3.10/3.13 的结果绑定[对应提交检查](https://github.com/SoberAming/codex-project-storage/actions/workflows/ci.yml)，不能继承旧版 CI 的通过结论。

维护者的真实大项目验证只形成具体清理计划，不删除项目或会话数据。隔离测试通过不代表任意业务项目、每种 Agent 宿主、个人外盘或完整 APFS 共享/快照语义均已验收。

## 使用

在原有分析请求中增加“如果扫描达到上限，按任务分批续扫；优先核验不用的历史构建；共享文件逐个保留，给出准确清单和收益”。Agent 管理清单、评审、哈希与执行回执，用户决定具体方案。

详细步骤见[分批清单](../references/batched-inventory.md)和[历史构建规则](../references/historical-builds.md)。已有计划不跨版本重放；重新读取当前现场、生成新计划并复核既有授权范围。
