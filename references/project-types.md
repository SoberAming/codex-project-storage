# 不同项目的空间分析与处理路线

画像先解释占用，执行器再限定操作。下表是覆盖线索，不是删除白名单；混合工程可以同时命中多类，未识别工程仍按元数据、生产依据和引用分析。

| 项目/工具链 | 常见大项 | 要核实什么 | 处理路线 |
| --- | --- | --- | --- |
| Node、Next、Vite、Remotion | node_modules、多工作树依赖、.next、dist、渲染与媒体中间件 | 本地/补丁依赖、部署目录、生产者、交付链、活动构建 | 依赖/构建默认保留；符合条件的媒体中间件走生成产物；停用导出可归档 |
| Python、uv、pip、Poetry | 环境、轮子/HTTP缓存、pyc、数据/模型 | 环境是否共用、缓存真实归属、解释器版本、符号链接依赖 | 严格 pyc 执行；极窄专用 pip 原生路线；uv/其他缓存先建议 |
| Rust、Go | target、模块/编译缓存、工具链 | workspace共享、Cargo凭据/安装记录、Go共享module cache | 大小可解释，工具专用方案；不删整个 Cargo/Go 根 |
| Java、Gradle、Maven | build、.gradle、依赖库、多版本SDK | 活动daemon、构建插件、离线依赖、其他项目引用 | 依赖/环境保护，核实官方清理行为；不盲跑工程任务 |
| .NET、CMake/C++ | bin/obj、构建树、NuGet、编译器、符号 | 自定义构建目标、调试/交付符号、源和输出是否混合 | 按范围提方案，通用工具不执行未知 clean |
| Flutter、Android、Xcode | SDK、模拟器、DerivedData、Gradle、构建包 | SDK/模拟器共享、设备状态、归档和签名 | 画像/建议；原生管理另核实，签名和发布档保留 |
| Playwright、Cypress、网页测试 | 浏览器包、录屏、trace、截图、profile | 登录资料、失败证据、视觉基准、工具下载共用关系 | 浏览器/profile/trace不通删；可重建普通预览仅满足生成规则才处理 |
| 隔离测试服务与合成数据库 | 每次运行新初始化的测试数据、多套历史运行 | 真实生产器、合成输入、对应运行结束、日志结果保留、当前引用及活动 | 已正向证明的合成PG测试data走独立退役器；业务库、恢复资料及其他未知运行保留并说明缺口 |
| 视频、设计、动画、音频 | 解码帧、代理/预览、重复导出、原素材、工程、AI产物 | 输入及生产链、确定性、编辑引用、交付/恢复需要 | 独立中间产物可精确删除；停用有价值产物迁移；原件/成片/唯一结果保护 |
| 数据、ML、研究、Notebook | 数据集、模型、checkpoint、实验输出、下载 | 原始/衍生区分、训练成本、许可证、可获取性、唯一实验结果 | 默认保护数据与权重；仅经明确证明的普通媒体中间件可用现有执行器，其余专案 |
| 游戏、CAD、文档或无manifest目录 | 引擎库、素材、设计源、导出、备份、临时任务 | 保存关系、编辑软件引用、是否只剩一份、专有格式 | 仍提供画像和方案；不因没有manifest停止，也不因叫Library就自动删 |

## 画像的测量口径

`project_profiler.py inspect` 对普通文件进行有上限的元数据遍历。`.git`、环境、依赖、构建、数据、媒体和状态的体积也计入解释，但不因此授权操作。`nodes` 是互斥归属分区，不能再与其父目录子树总量相加。

默认 `--max-files 100000`、单配置 `--max-config-bytes 1048576`；达到上限、权限错误、重解析点/符号链接等写入缺口，不伪称完整。可按预算调整边界；不能为凑完整一次性展开整块盘。

外部路径是线索，不是递归入口。`--related-root` 必须是明确授权、范围清楚的关联目录；它与项目数据分列，跨根硬链接身份避免重复计数。关联数据的归属仍可能未知，不输出可释放承诺。全局缓存默认仅发现存在性、测量未知。

工具只读允许清单内的配置片段；不执行manifest内脚本，不读取依赖包内部manifest来扩展工程，不扫描`.env`、会话、凭据或业务正文。Git worktree指针有大小上限，仅解释关联，不沿指针递归进入外部Git元数据。CODEX_HOME/CODEX_SQLITE_HOME不能作为项目或related-root递归入口。

可以用 `--scan-json ABS_SCAN.json` 复用同项目、同文件身份/大小/时间且仍匹配的历史**逐文件分配量**；不叠加历史汇总。未知身份、敏感路径或不匹配条目不复用。两种扫描器覆盖不同，不能用其总量差作为增长证明。

## 给用户的方案

只展示主要来源、推荐动作、可核实收益和取回/重建影响。把“占了多少”与“能删多少”分开；依赖很大也可能完全需要。不认识的栈以证据不足保留，agent继续查说明/配置/真实任务记录，避免让用户逐个判断技术目录。

`review_priorities`仅对已观测的互斥分区进行类别汇总，列出覆盖主要占用的类别与下一项证据，不新增正文读取或删除权限。名称类似隔离PG运行的data会标作`isolated_runtime_clue`，不是已确认测试库；普通业务pgdata不会因此变成可丢弃对象。队列中释放授权和已执行量均为0，后续精确计划与回执才能产生收益数字。

少量pyc占项目不足1%时会提示“小缓存方案风险”。agent应完成大项用途和生命周期判断，给出可执行方案或具体保护理由；不能为追求比例删除必需依赖和业务资料。npm只有经过独占归属、真实生产与版本布局核验才进入专用适配器。
