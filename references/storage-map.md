# Codex 与项目存储机制

资料核对日期：2026-11-14。路径/数据库私有结构可能随版本变化，运行时发现优先于示例。官方机制与本工具保守规则分开使用。

## 哪些数据为什么增长

| 层次 | 典型内容 | 增长机制与处理原则 |
| --- | --- | --- |
| Codex 用户状态 | CODEX_HOME 下配置、认证、历史、日志及缓存 | 默认根为 `~/.codex`；不等于当前项目数据，不能按项目清理 |
| 会话与索引 | sessions、archived_sessions、history.jsonl、session_index.jsonl、SQLite 及 sidecar 等版本相关名称 | CODEX_SQLITE_HOME或sqlite_home配置可能另设数据库根；会话正文与索引配合恢复上下文。有些路径可能是迁移联接。只报告，不写库、不截断、不删除，不读认证正文 |
| Git 工作树 | 宿主可配置的工作树根，或用户自行创建的工作树 | 并行工作有各自检出文件和依赖/构建缓存，不能按“目录旧”回收。优先使用当前宿主提供的工作树管理功能，保存必要ignored文件 |
| 项目依赖/构建 | node_modules、虚拟环境、.next/cache、Python 字节码 | 工具运行生成，可重建不等于可随时删除；整套依赖可能含补丁/本地包，单独评估 |
| 任务产物 | 截图、浏览器录制、音视频中间件、输出、验收与回退包 | 通常来自项目工具或 agent 调用的脚本；不能一概说成 Codex 内置缓存。确认生产者、唯一性和用途后再分级 |
| 浏览器运行环境 | 浏览器下载、临时配置与持久登录目录 | 公共下载与登录状态不同；登录配置可能包含 Cookie，默认保护，不随缓存删除 |
| 操作系统/软件共用缓存 | TEMP、包管理器、编辑器与媒体软件数据 | 单个项目无法证明归属；只列关联，不随项目执行器删除 |

常见浪费源：重复创建依赖环境；多次渲染/解码保留中间文件；无保留期的任务输出；多个工作树分别下载依赖与浏览器；本地包路径错误造成重复项目副本；工具输出把大段日志/编码内容写入会话。这些是需要检查的原因，不是扫描前就确认的结论。

`file:..` 等本地依赖、脚本的显式输出路径、`tempfile` 的 `dir=` 参数等会绕过系统 TEMP。改变 TEMP 不能解决所有项目增长。不能因为目录前缀含 Codex 就断定官方应用负责写入。

## 关联表如何建立

记录“逻辑入口 → 实际目标 → 读写方 → 项目归属 → 证据 → 当前用途”。例如项目配置引用外部素材，素材仍在保护范围；全局工作树或共享 cache 即使名字包含项目名，也不能直接确认项目独占。

优先检查目录元数据、Git 根、生产脚本的少量路径配置和已存在的报告。SQLite 如确有诊断必要，只能用经过版本核实的只读方式读取必要列；不导出正文、凭据，不执行 VACUUM、DELETE、PRAGMA 写配置或直接编辑索引。本执行器完全不打开数据库。

不把 scan 的未引用当成孤儿证明：当前项目配置找不到引用，不代表另一个项目、旧会话或外部编辑软件没有引用。未知共享状态保留。

## 度量与证据限制

- 逻辑长度用于解释文件内容规模；物理分配才接近磁盘成本。压缩/稀疏、硬链接、APFS 克隆/快照、回收站/废纸篓和文件系统元数据会影响可回收值。
- Windows 以文件系统报告的分配量为准，macOS 通常使用 `st_blocks * 512`；系统不提供时标未知。外盘 exFAT 的簇大小可能让大量小文件占用增加。
- 扫描跳过目录联接、符号链接和其他重解析点，不把目标再加一遍；硬链接按身份去重。跳过区、权限错误、扫描上限都属于覆盖限制。
- 两份相同范围、相同策略、完整覆盖的报告才适合比较净增长。修改时间是线索，不能独自证明写入软件或文件无用。
- 操作系统空闲差值包含其他程序同期写入，也可能受快照保留影响，不能保证等于已删文件长度。

## 官方依据

- [Advanced Configuration](https://learn.chatgpt.com/docs/config-file/config-advanced)：CODEX_HOME、项目配置、history.persistence 与 history.max_bytes。`history.max_bytes` 针对文档所述历史文件，不是 sessions 或各类 SQLite 的通用容量上限；关闭历史会改变保留行为，本 skill 不自动设置。
- [Environment variables](https://learn.chatgpt.com/docs/config-file/environment-variables)：CODEX_HOME与独立的CODEX_SQLITE_HOME；`sqlite_home`配置可覆盖后者，运行时应核实真实根。
- [Git worktrees](https://learn.chatgpt.com/docs/environments/git-worktrees)：并行检出、各自依赖/缓存、工作树与会话关系及宿主管理方式。依赖与未提交内容需保护，清理应走当前版本支持的管理入口。
- [Build skills](https://learn.chatgpt.com/docs/build-skills)：SKILL.md 结构、显式/隐式调用与 `.agents/skills` 发现路径。宿主也可能提供旧版技能目录，安装时遵循实际宿主位置。

上述文档不定义本 skill 的逐文件清理白名单。白名单是本工具为了保护项目而施加的额外限制，不能据此推断所有其他数据都可以清理。
